Universal Tenant Experience — initial manual operations (Alan)
Use existing /sf-pilot/staff. Universal tenant requests · Rofo only is separate from legacy SF published shortlists. Check the queue regularly; no automatic notification or message is sent.
1 Read submitted details alongside the current canonical Brief revision. Do not assume the submitted email is verified. If needed, use the existing Rofo mailbox to send only a minimal verification note without private search details. An identifiable reply from that exact address is the evidence. Record thread/date and the affirmative reply in Record verified tenant mailbox; do not enter credentials/tokens.
2 For a direct tenant reply: choose Reply only to verified tenant, check the current packet immediately before sending manually, use only its verified address, then record Sent with message evidence, Confirmed not sent, or Uncertain. Never retry an uncertain/prepared attempt without reconciliation. The application does not send mail for you.
3 For an introduction: verify the actual professional/role/address and record evidence. Prepare permission request. Tenant can approve from the original browser's valid30day Brief owner cookie. Normal Brief URL contains no token and cannot grant another browser access.
4 If the tenant cannot reopen the Brief, use the verified mailbox to obtain an affirmative reply approving the exact named recipient/address/role, purpose and complete information. Record specific tenant email approval against the displayed exact packet. This does not restore browser access or allow Brief edits. General help requests are not introduction permission.
5 Immediately before manual sharing choose Introduction to explicitly approved recipient and Check current packet. Send only that exact packet to that recipient through the existing mailbox, then record outcome/evidence. Do not CC/BCC others or alter destination/payload. Changed requirements/recipient need fresh approval. Recheck if delayed. Database checks cannot atomically control a separate mailbox send; operator discipline is required.
6 Record tenant withdrawals from verified mailbox using Record tenant withdrawal, including if their browser expired. Stop pending sharing. A completed send cannot be recalled by changing database status. Record historical uncertain/sent outcomes even after requirements change/withdrawal; never fabricate success.
7 Requests/permissions are not referrals. Do not use generic lead/OfficeFinder forms for these records. No automatic research, quoting, booking or external inquiries. Keep provenance, price units and unconfirmed availability clear.
Release/disable: same guarded code with UNIVERSAL_TENANT_EXPERIENCE_ENABLED=false at build/runtime, outbound off; retain0011 and all history. No destructive rollback or blind revert to pre-universal code. Existing SF_PILOT_EMAIL_SEND_ENABLED=false and SF_PILOT_MAIL_MODE=disabled keep legacy pilot sending off during validation. Universal fulfillment is manual; there is no new automatic sender switch.
